# QingYan v0.3.0

本版本将运行数据库从 SQLite 切换为 PostgreSQL 18，是 `0.x` 阶段的一次破坏性版本升级。现有 SQLite 实例必须停写转换后切换，不能直接执行普通更新脚本或把旧导出文件导入新库。

## 数据库与运维

- PostgreSQL 成为唯一运行数据库；保留独立 SQLite 离线转换器，提供 `analyze`、`convert`、`verify`、`apply-config` 四个操作。
- 转换保留有效业务数据、凭据 hash、权限和通知结果，完整旧库及退役历史另行归档；逐表逐字段核对后单独切换配置。
- PostgreSQL 备份使用 custom dump，恢复写入预建空目标库并生成新配置；后台导入导出、安装导出文件恢复及定时备份退出。
- 新增独立安装器与源码缓存分离布局，支持连接已经安装的 PostgreSQL。已有数据库无需重新安装容器。

## 评论、后台与通知

- 增加站点邮箱使用规则、受保护域名与后台账号发言权限校验。
- 增加主体/IP 突发额度、持续违规处罚、解除与恢复，支持显式启用受限 1Panel 网关同步。
- 完善本地后置审核、评论邮件内容与投递状态，修复后台分区保存、未保存保护和错误恢复流程。

## 从 v0.2.5 升级

1. 固定本版本源码和镜像，保留旧镜像、配置、安装锁及同一时点的 SQLite 与本地资源。
2. 使用已安装的 PostgreSQL 18 和已创建的空数据库；连接信息由运维提供，应用容器加入对应数据库网络。
3. 停止旧应用及所有写入者，使用本版本镜像运行独立转换器。转换器创建目标 schema，无需先执行 `db:migrate` 或安装向导。
4. 完成 `convert` 与 `verify`，确认 `verified=true`、`configurationSwitchReady=true`，再执行 `apply-config`。
5. 切换应用镜像并核对环境变量、卷和网络，启动后检查 `normal_current`、后台登录、评论读取与写入、通知和 IP 库。

完整命令与回滚边界见 [SQLite 到 PostgreSQL 离线转换与切换](../postgresql-conversion.md)。已有 PostgreSQL 实例的常规更新见 [部署指南](../deployment.md#更新流程)。
